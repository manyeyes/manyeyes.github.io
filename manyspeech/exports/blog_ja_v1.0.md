# X-ASR-zh-en：軽量高精度中英バイリンガル・オフライン＆ストリーミング音声認識モデル

## 一、プロジェクト背景と開発チーム

### 1.1 業界の開発背景

ローカルでのオフライン音声対話、プライバシーを重視したリアルタイム文字起こし、中英バイリンガル混在音声認識といった主流のニーズに対して、既存のオープンソースASRモデルには多くの課題があります。パラメータ数の多いモデルはデプロイコストが高く軽量化が難しく、軽量モデルはバイリンガル精度の不足、ストリーミングとオフライン推論の非互換、汎化性能の弱さなどの問題を抱えています。これらの核心的な課題を解決するため、複数の大学の研究チームが連携して**X-ASR-zh-en 中英バイリンガル・オフライン＆ストリーミング統一ASRモデル**を開発しました。超軽量ボリューム、高精度、低遅延、両モード統一対応を特徴とし、学術研究と産業向け軽量実装の両方のニーズを満たし、開発者に低コストで低障壁なバイリンガル音声認識ソリューションを提供します。

### 1.2 開発チームとオープンソース宣言

**開発機関**：上海交通大学、上海創智学院が主導し、复旦大学、華中科技大学など複数の大学の研究力と連携して開発された産学連携による軽量音声認識のオープンソース成果です。

**オープンソースライセンス**：本モデルは **Apache 2.0 ライセンス** の下で正式に公開され、重み、ソースコード、デプロイリソースが完全にオープンです。**個人学習、学術研究、無償での商用利用** が可能で、追加の許諾は不要です。

## 二、モデルの概要

X-ASR-zh-en は、Icefall、K2 フレームワークと Zipformer Transducer アーキテクチャを基に構築された軽量中英バイリンガル統一音声認識モデルです。**100万時間** のオープンおよび収集によるバイリンガル音声データで訓練され、パラメータ数はわずか **0.16B** という超小規模です。最大の特徴は **単一モデルでストリーミング（リアルタイム）認識とオフライン高精度認識の両モードを統一推論** できることで、重みやコードロジックの切り替えは不要です。

モデルは多粒度の低遅延推論にネイティブ対応しており、160ms / 480ms / 960ms / 1920ms の4つの標準チャンクモードを提供します。また、中英混在認識、自動句読点付与、英文の大文字・小文字正規化をネイティブサポートしています。ONNX 量子化最適化により、CPU のみで低遅延推論が可能で、GPU やクラウドへのデータ送信は不要です。極限の軽量デプロイと高精度認識を両立しており、総合性能は同クラスの軽量オープンソースASRモデルを大きく上回ります。

## 三、コアアーキテクチャと主要機能

### 3.1 アーキテクチャの強み

業界で先進的な Zipformer Transducer 効率的時系列モデリングアーキテクチャを採用しています。従来の CNN や RNN と比較して、長い時系列のコンテキストモデリング能力に優れ、長文音声や複雑環境下での認識誤差を効果的に低減できます。Icefall、K2 フレームワークによる精緻な訓練スケジューリングにより、収束安定性と中英バイリンガルの汎化能力が大幅に向上しており、極小パラメータで高精度な両モード推論を実現する基盤アーキテクチャとなっています。

### 3.2 主な機能

- **両モード統一推論**：単一モデル・単一の重みで、リアルタイムストリーミング復号とオフライン一括復号の両方をネイティブサポート。あらゆる音声認識業務シナリオに対応。
- **多粒度低遅延対応**：160ms、480ms、960ms、1920ms の4段階の推論チャンクを内蔵。超低遅延のライブ配信、標準的な会議文字起こし、長音声の一括認識など、異なる遅延要件のシナリオに柔軟に適応。
- **ネイティブ中英バイリンガル能力**：統一バイリンガルモデリングにより、中英混在音声を高精度に認識。出力には自動で正しい句読点と英文の大文字・小文字が付与される。
- **ゼロ・コンピューティング依存デプロイ**：0.16B の超軽量パラメータにより、CPU のみでの推論が可能。ONNX 量子化最適化により、エッジ端末からサーバーまで迅速な軽量デプロイが実現。
- **標準化されたオープンソースデプロイ**：[Sherpa-ONNX](https://github.com/k2-fsa/sherpa-onnx) 公式デプロイエコシステムにネイティブ対応。完全な ONNX 推論ファイル、サーバースクリプト、テストツールが付属し、すぐに使えて拡張性も高い。

## 五、推論デプロイ

X-ASR-zh-en 公式推奨のランタイムは [**Sherpa-ONNX**](https://github.com/k2-fsa/sherpa-onnx) です。本モデルはこのオープンソースデプロイエコシステムにネイティブ対応しており、完全な ONNX 推論ファイル、サーバースクリプト、テストツールが付属しています。プロフェッショナル開発者向けのプロジェクト統合、バッチ推論、WebSocket ストリーミングサービスなどのエンジニアリングシナリオに対応します。ユーザーのニーズに合わせて、公式標準デプロイ方法と軽量クイック体験方法の両方を提供します。

### 5.1 公式標準デプロイ：Sherpa-ONNX によるエンジニアリングデプロイ

プロジェクトリポジトリには完全な Sherpa-ONNX デプロイリソースが含まれており、異なるチャンクサイズの ONNX エンコーダ・デコーダ・ジョイナーの重みファイル、および付属の推論スクリプトが用意されています。CPU のみでの軽量ストリーミングサービスのデプロイが可能で、リアルタイム音声認識サービスを迅速に構築でき、プロジェクトの二次開発や実サービスへの実装に適しています。

#### 環境デプロイ手順

プロジェクトリソースをダウンロード後、deployment ディレクトリに移動し、仮想環境を作成して依存パッケージをインストールします。

```bash
cd deployment
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

#### ストリーミング推論サービスの起動

160ms 低遅延モデルを例として、CPU ストリーミング認識サービスを起動します。ポート、スレッド数、復号パラメータはカスタマイズ可能です。

```bash
python infer_and_client/sherpa_streaming_server.py \
  --host 0.0.0.0 \
  --port 8766 \
  --tokens models/chunk-160ms-model/tokens.txt \
  --encoder models/chunk-160ms-model/encoder-160ms.onnx \
  --decoder models/chunk-160ms-model/decoder-160ms.onnx \
  --joiner models/chunk-160ms-model/joiner-160ms.onnx \
  --provider cpu \
  --sample-rate 16000 \
  --feature-dim 80 \
  --num-threads 1 \
  --decoding-method greedy_search \
  --model-type zipformer2 \
  --enable-endpoint-detection 0 \
  --text-format none
```

#### 音声ファイルを用いたテスト推論

サービス起動後、クライアントスクリプトを使ってローカルの WAV 音声を読み込み、リアルタイムストリーミング推論をシミュレーションしてテストできます。

```bash
python infer_and_client/sherpa_streaming_client.py \
  --server-uri ws://127.0.0.1:8766 \
  --wav /path/to/test.wav \
  --chunk-ms 100 \
  --simulate-realtime 1
```

### 5.2 極簡推論：ManySpeech-CLI コマンドライン（クイック体験）

**[ManySpeech](https://github.com/manyeyes/ManySpeech)** はオープンソースの音声 AI モデル推論プロジェクトであり、汎用 ONNX 音声モデル推論 SDK として利用できます。開発者は二次開発や機能拡張が可能で、様々な軽量音声認識モデルの実装に適しています。**ManySpeech-CLI** は ManySpeech カーネルをベースにした軽量コマンドラインツールで、複雑な開発設定を取り除き、ゼロコンフィグで即座に使えることを目指しています。一般ユーザーがモデルの効果を簡単に試したり、開発者が日常的な機能検証を行うのに最適です。

本ツールは X-ASR-zh-en の全モデルと完全互換性があり、マイクからのリアルタイム音声取り込み、ストリーミングリアルタイム復号、中英混在認識、自動句読点付与、大文字・小文字正規化をサポートします。重みの手動読み込みや複雑なエンジニアリングデプロイは不要で、モデル性能を素早く検証するための最適な軽量ソリューションです。

#### ターミナルでのリアルタイムマイク推論の使用方法

[ManySpeech-CLI のインストール](https://manyeyes.github.io/manyspeech/cli/getting-started/installation.html) 後、以下のコマンドを実行するだけで、低遅延リアルタイム中英バイリンガル音声認識が開始されます。

```bash
manyspeech asr -t online -md k2transducer-zipformer-x-asr-zh-en-480ms-onnx-online-20260601 -m chunk -i mic
```

#### 主要コマンドパラメータの説明

- **-t online**：リアルタイムストリーミング推論モードを指定。マイクからのリアルタイム音声入力に適応し、低遅延出力を保証します。
- **-md k2transducer-zipformer-x-asr-zh-en-480ms-onnx-online-20260601**：480ms 均衡版モデルをロード。認識精度と推論遅延のバランスが良く、ほとんどの日常・オフィスシナリオに適しています。
- **-m chunk**：チャンクストリーミング推論機構を有効化。モデル本来の復号アーキテクチャに適合し、安定した認識を実現します。
- **-i mic**：音声入力ソースとしてマイクを指定。リアルタイムで音声を収音し、即座に文字起こしします。

コマンド実行後、ターミナルは継続的にマイク入力を監視し、中英混在音声認識、句読点補完、英文大文字・小文字正規化を自動で行います。一般ユーザーはモデル能力を簡単に体験でき、開発者は ManySpeech オープンソースカーネルをベースに二次開発し、モデル推論能力を自身のプロジェクトに迅速に統合できます。

# Fun-ASR-Nano-2512：数千万時間の実音声で学習した800Mパラメータの音声認識大規模モデル

## 一、プロジェクト背景と開発チーム

Fun-ASR-Nano-2512シリーズは、**通義実験室（Tongyi Lab）** が **2025年12月15日** に正式公開したエンドツーエンド音声認識軽量モデルです。Fun-ASRファミリーの中でも、低計算リソースでの展開に特化した軽量化バージョンであり、認識精度を犠牲にすることなく、わずか800Mのパラメータで多様な音声シーンをカバーします。

通義実験室のFunチームは、これまでに産業グレードのASRモデル **Paraformer**、軽量音声認識モデル **SenseVoiceSmall** など数多くの製品をオープンソース化してきました。Fun-ASR-Nanoのリリースは、「軽量＋多言語＋産業レベルの堅牢性」という技術方向における最新の取り組みです。

中心的な研究論文「Fun-ASR Technical Report」はarXiv（2509.12508）にアップロードされており、2025年9月に初版が提出され、その後4回の改訂（v4は同年12月19日公開）を経て、データスケーリング、モデルサイズ拡張、LLM深層統合、強化学習など多角的な技術経路が詳述されています。著者は38名におよび、音声認識、大規模言語モデル、強化学習など複数の研究領域をカバーしています。

## 二、モデル全体概要と言語能力

本シリーズには2つのコアバージョンがあり、いずれも **8億（800M）パラメータ** です：

| モデル名 | パラメータ数 | サポート言語範囲 | コア特徴 |
| :--- | :--- | :--- | :--- |
| **Fun-ASR-Nano-2512** | 800M | 中国語（7大方言＋26アクセント）、英語、日本語 | 中国語方言・アクセント、音楽背景での歌詞認識、ラップ音声認識に深く最適化 |
| **Fun-ASR-MLT-Nano-2512** | 800M | 31言語 | 多言語の自由な切り替えと混在認識 |

全シリーズで低遅延リアルタイム文字起こし、句読点復元、タイムスタンプ出力をサポート。**公式のPyTorchモデル**を提供。コミュニティは公式モデルを基にONNX形式の最適化版も公開（「コミュニティによるデプロイ」節を参照）。クラウドGPUからエッジCPUまで柔軟にデプロイ可能。

#### 2.1.3 英語と日本語の認識

英語・日本語のサポートは「聞こえる」だけでなく「正確に聞き取る」ことを重視：

モデルは **中・英・日三者共同アライメント学習** の統一アーキテクチャを採用。言語横断的な共有音響表現空間を確立し、中英混在や日英混在などの実環境に適応します。

## 三、コアアーキテクチャとコア能力

### 3.1 4コンポーネントエンドツーエンドアーキテクチャ

1. **音響エンコーダ**（200M）：生音声から音響特徴を抽出、時系列依存関係をモデル化。
2. **CTCデコーダ**：並列分岐。リアルタイム性と精度のバランスをとりつつ一次的な書き起こしを出力。
3. **Adaptorモジュール**：音声特徴空間とテキスト特徴空間を位置合わせ。音声とテキストのモダリティ間の表現ギャップを埋める。
4. **LLMデコーダ**（600M）：**Qwen3-0.6B** をベース。CTC出力に文脈意味情報を加えて高精度なテキスト生成を実行。

この「軽量エンコーダ＋コンパクトデコーダ」設計により、総パラメータ数は **0.8B** に正確に制御されています。

### 3.2 LLMとCTCのデュアルブランチ設計

- **LLM拡張ブランチ**：LLMデコーダを主出力とし、高い文脈理解力と幻覚抑制能力を持つ。
- **CTC軽量ブランチ**：CTCデコーダを主出力とし、レイテンシ重視・計算リソースが制限された環境に適する。

### 3.3 アーキテクチャの革新

- **テキスト知識注入**：音響エンコーダの事前学習時に、テキストLLMであるQwen3の層を用いて初期化。テキスト世界の言語学知識を音声表現学習に「注入」する。
- **RAGホットワード機構**：推論時にドメイン固有のキーワードを動的に導入。**最大1000以上** のカスタムホットワードをサポートし、専門分野のキーワード認識精度を大幅に向上。

## 四、学習データと戦略

### 4.1 データ規模

事前学習には **数千万時間** の音声データを使用。無ラベル実音声とラベル付き音声-テキストペアを包含。教師あり微調整では **数百万時間** のマルチソースデータ（手動書き起こし、疑似ラベル、環境雑音拡張、TTS合成、模擬ストリーミング、ホットワードカスタマイズなど）を統合。

### 4.2 データソースとドメインカバレッジ

事前学習の実音声は **AI、EC、教育、交通** などの垂直産業をカバー。ラベル付きペアは主に **中国語と英語** で構築。微調整フェーズでさらにカバレッジを拡大し、**雑音ロバスト性、コードスイッチング、ホットワードカスタマイズ** などの産業シーン向けにカスタマイズデータを合成。さらに、**インターネット、テクノロジー、住宅改装、保険、畜産、自動車** など十数業界の専門用語を網羅するため、**億時間超** の音声データで学習。

### 4.3 データ前処理とアノテーション戦略

- **アノテーション構築**：Paraformer-V2、Whisper、SenseVoiceの3つの独立したASRシステムで並列疑似ラベルを生成し、コンセンサス機構で高信頼度の結果を選択。
- **データフィルタリング**：VADを用いて無音区間や低品質音声を除去。
- **コンテキスト拡張**：Qwen3で訓練テキストからキーワードを自動抽出し、コンテキストプロンプト付き訓練サンプルを構築。
- **データ拡張**：**11万時間のクリーン音声＋1万時間の雑音混合** の拡張雑音データセットを別途構築。CosyVoice3 TTSでアクセント付き音声を合成し、クリーン音声に空港・駅など6種類の環境雑音を重畳。

### 4.4 方言・アクセントデータの特化

方言は **呉語・粤語・閩語・客家語・贛語・湘語・晋語** の七大方言をカバー。アクセントは **河南、陝西、湖北、四川、重慶、雲南、貴州、広東、広西** など26地域。各カテゴリごとに専用の収集・アノテーションを実施。

### 4.5 学習戦略

**三段階漸進的学習：**

1. **大規模事前学習**：数千万時間のデータで音響理解と言語-テキスト位置合わせを確立。
2. **多段階教師あり微調整（SFT）** ：数百万時間のマルチソースデータで産業シーン向けに細調整。
3. **強化学習微調整（RLHF）** ：**FunRL** フレームワークを使用。約10万の困難サンプルに対し、キーワード再現率、幻覚ペナルティ、言語一貫性などの報酬関数を設計し、幻覚率を大幅に低減。

**特化学習：**
- **耐雑音学習**：複雑雑音環境のテストセットで平均相対性能を約 **13%** 向上。
- **ストリーミング能力学習**：ストリーミング復号を模擬した訓練データを構築し、訓練-推論のミスマッチを低減。

## 六、推論・デプロイ

### 1. 公式推論（PyTorchオリジナル）

```python
from funasr import AutoModel

model = AutoModel(
    model="FunAudioLLM/Fun-ASR-Nano-2512",  # または Fun-ASR-MLT-Nano-2512
    trust_remote_code=True,
    remote_code="./model.py",  # GitHubリポジトリから取得
    device="cuda:0"            # または "cpu"
)

res = model.generate(
    input=["path/to/audio.mp3"],
    language="Chinese",        # MLT版は "auto"
    itn=True,
    hotwords=["custom hotword"],
    output_timestamp=True
)
print(res[0]["text"])
```

> **注**：`remote_code` は [Fun-ASR GitHubリポジトリ](https://github.com/FunAudioLLM/Fun-ASR) からダウンロードした `model.py` を指す。公式モデルは句読点復元、タイムスタンプ、ITN、ホットワードの全機能をサポート。

# FireRedASR2-AED：軽量高精度中英バイリンガル音声認識モデル

## 一、モデル概要

FireRedASR2-AEDは、小红书のFireRedTeamが発表した第2世代産業グレード音声認識モデルであり、統合システムFireRedASR2Sの中核ASRモジュールです。FireRedASR2シリーズの2つの変種のうち、AEDバージョンは **Attention-based Encoder-Decoder（AED）** アーキテクチャを採用しており、パラメータ数は約1B+です。これは、FireRedASR2-LLM（8B+パラメータ）大規模モデルの軽量な代替手段です。

FireRedASR2は、初代FireRedASRをベースに認識精度を全面的に向上させ、優れたパフォーマンスと最適な効率の両方を異なるシーンで実現するように設計されています。

## 二、コアアーキテクチャ設計

初代FireRedASR-AEDの技術文書（arXiv:2501.14350）に基づく、FireRedASR2-AEDの中核アーキテクチャは以下の通りです。

### 2.1 エンコーダ-デコーダ構造

**Conformerエンコーダ＋Transformerデコーダ** の古典的な組み合わせを採用：
- **Conformerエンコーダ**：マルチヘッド自己注意機構と畳み込みモジュールを組み合わせることで、音声信号の大局的依存関係と局所的な音響特徴の詳細なモデリングを両立。
- **Transformerデコーダ**：交差注意機構を介して効率的な系列変換を実現し、自己回帰デコードをサポート。

### 2.2 サブサンプリング戦略

エンコーダ前端は **2層の畳み込み（ストライド2、カーネルサイズ3）** により入力音声をサブサンプリングし、時間分解能を10msから40msに低減。重要な音響情報を保持しつつ計算複雑性を効果的に削減します。

### 2.3 トークナイゼーション戦略

**ハイブリッドトークナイゼーション戦略** を採用：中国語は文字レベル、英語はByte Pair Encoding（BPE）を使用。**総語彙サイズ7,832** であり、中英混合入力の認識シーンに自然に対応します。

### 2.4 入力長の制限（公式仕様）

- **FireRedASR2-AED**：最大 **60秒** の音声入力をサポート。60秒を超えると幻覚が発生する可能性があり、200秒を超えると位置エンコーディングエラーが発生します。
- **FireRedASR2-LLM**：最大 **40秒** の音声入力をサポート（より長い入力は未テスト）。

## 三、学習データと戦略

初代FireRedASR-AEDの技術文書（arXiv:2501.14350）によると、学習データは以下の通りです。

- **普通話コーパス**：約 **70,000時間** の専門家による書き起こし高品質音声データ。主に人手アノテーション。
- **英語データ**：約 **11,000時間** の補足学習データ。バイリンガル認識能力を確保。

学習にはプログレッシブ正則化戦略を採用し、DropoutとSpecAugmentを徐々に導入して収束の安定性を確保しています。

### 6.4 基本使用法：ASRモジュール（Python API）

ASRモジュールのみを呼び出して音声認識を実行し、文字レベルタイムスタンプを出力します。

```python
from fireredasr2s.fireredasr2 import FireRedAsr2, FireRedAsr2Config

# ASRパラメータの設定
asr_config = FireRedAsr2Config(
    use_gpu=True,           # GPUを使用するか
    use_half=False,         # 半精度を使用するか
    beam_size=3,            # ビームサーチ幅
    nbest=1,                # 返す最良候補数
    decode_max_len=0,       # 最大デコード長（0=自動）
    softmax_smoothing=1.25, # Softmax平滑化係数
    aed_length_penalty=0.6, # 長さペナルティ係数
    eos_penalty=1.0,        # 終端記号ペナルティ
    return_timestamp=True   # 文字レベルタイムスタンプを返す
)

# モデルのロード
model = FireRedAsr2.from_pretrained("aed", "./pretrained_models/FireRedASR2-AED", asr_config)

# 認識の実行
results = model.transcribe(["utt1", "utt2"], ["test1.wav", "test2.wav"])
for res in results:
    print(f"テキスト: {res['text']}")
    print(f"信頼度: {res['confidence']}")
    print(f"文字レベルタイムスタンプ: {res['timestamp']}")  # 形式: [('你', 0.42, 0.66), ...]
```

### 6.5 高度な使用法：統合システム（VAD＋LID＋Punc搭載）

音声活動検出、言語識別、音声認識、句読点予測を自動的に一貫して実行します。

```python
from fireredasr2s import FireRedAsr2System, FireRedAsr2SystemConfig

# デフォルト設定で初期化（VAD、LID、ASR、Puncモジュールを自動ロード）
asr_system_config = FireRedAsr2SystemConfig() 
asr_system = FireRedAsr2System(asr_system_config)

# 単一の音声ファイルを処理
result = asr_system.process("test.wav")

print(f"完全なテキスト: {result['text']}")          # 句読点付きテキスト
print(f"文レベル情報: {result['sentences']}")   # 各文の開始・終了時間、言語、信頼度
print(f"VADセグメント: {result['vad_segments_ms']}") # 音声セグメントの開始・終了時間（ミリ秒）
print(f"文字レベルタイムスタンプ: {result['words']}")       # 各文字の開始・終了時間
```
